# DMUI4 API 框架

DMUI4 是一个为 Roblox 客户端执行器（Client-side Executor）设计的现代化、全功能 Lua UI 框架与脚本库。项目采用模块化设计，提供丰富的 UI 组件、全局状态管理、多语言支持以及多种游戏内实用功能。

## 核心特性

*   **多语言系统**：内置基于 `UITranslationsLau()` 的统一翻译字典与 `BindText` 辅助函数，原生支持简体中文、繁体中文、英语、日语、西班牙语和葡萄牙
语的无缝热切换。

*   **动态右键菜单**：支持基于按钮绑定的自定义右键菜单，完美适配 PC 端（左键/右键）与移动端（轻点/长按 3 秒），带有滚动、屏幕边缘自适应及多语言动态重绑。

*   **高度定制化 UI 组件**：内置模板窗口（`BuildWinUI`），支持自定义拖拽、全屏、缩放、最小化到任务栏。集成实时列表滚动条及动态光泽特效。

*   **玩家档案系统**：支持输入 UserId 或用户名查询。可获取账户创建时间、年龄、好友、封禁状态、粉丝/关注数等。并在 3D 视口中渲染支持拖拽旋转、缩放的玩家虚拟形象。

*   **通知与历史系统**：支持多位置提示、超时自动关闭、按钮交互。内置独立的通知历史记录窗口，支持持久化保存与动态清理（Keep 机制）。

*   **游戏实用功能集成**：

    *   **统一飞行**：整合标准、载具、移动端、CFrame 四种飞行模式，支持速度动态调节。

    *   **观战系统**：自动跟随目标重生，防视角重置，退出时安全恢复本地视角。

    *   **实时定位**：基于 ViewportFrame 计算目标相对距离与方向，显示 3D 箭头引导。

    *   **对象/玩家选择器**：提供标准化的 UI 供脚本调用以选择游戏内的模型、部件或在线玩家。

# 插件

DMUI 从诞生之初就不只是一个简单的“功能脚本”，它的核心定位是一个**拥有完整 UI 交互与基础能力底座的前端框架**。在主脚本中预留 `PluginAPI` 模块，正是为了鼓励开发者以“插件”的形式来扩展功能。

采用插件化架构不仅是为了方便开发者，更是为了解决许多现实工程中遇到的瓶颈。以下是为什么要在 DMUI 内编写插件的核心原因：

### 1. 解决多游戏服务器的兼容性瓶颈（主脚本与插件互补）

Roblox 上有数以万计的游戏，每个游戏的服务器架构、反作弊机制、特定玩法都截然不同。主脚本（DMUI 核心）如果试图将每一个特定游戏的功能（如特定游戏的自动任务、特殊交互等）全部内置，会导致代码极度臃肿，且极易因为频繁更新某个单一游戏的逻辑而引发整个框架的崩溃。**对于主脚本无法原生支持或难以兼顾的特定服务器/游戏功能，完全可以通过编写独立插件来替代和扩展。** 插件可以针对特定游戏进行深度定制和快速迭代，而不必等待主框架的更新，也不会影响主框架的稳定性。

### 2. 极速开发：无需重造轮子

从零编写一个独立脚本，往往需要花费大量时间处理 UI 绘制、窗口拖拽、分辨率自适应、通知弹窗、多语言翻译等非核心问题。而在 DMUI 中开发插件：
- 可以直接调用 `BuildWinUI` 生成统一风格、支持缩放和拖拽的模板窗口。
- 可以直接调用 `BindText` 和内置的翻译表，快速实现多语言。
- 可以直接使用现成的通知系统、玩家选择器、右键菜单等高级交互组件。
这极大缩短了开发周期，让开发者能将 100% 的精力投入到插件的核心业务逻辑上。

### 3. 统一的交互与视觉体验

如果每个功能都由不同的人编写，用户会面临五花八门的 UI 风格和不一致的操作逻辑。将功能作为 DMUI 插件开发，意味着所有插件共享同一套底层 UI 规范：同样的窗口聚焦动画、同样的右键菜单响应逻辑（自动适配 PC 与移动端）、同样的音效反馈与主题颜色。这保证了最终用户在面对任何第三方插件时，学习成本几乎为零。

### 4. 核心框架与业务逻辑的解耦

通过 `APIFold` 提供统一的接口调用（如飞行、观战、定位等），插件本身不需要关心底层是如何实现物理飞行的，也不需要关心观战是如何防止视角重置的。这种**高内聚、低耦合**的架构使得：
- 底层 API 的更新或 Bug 修复（例如修复了观战退出时视角恢复错误的问题）会瞬间惠及所有插件。
- 插件只需专注自身业务，即便插件内部逻辑出错，也不会轻易导致整个 DMUI 核心框架崩溃。

### 5. 赋能生态与轻量化运行

插件机制允许按需加载。用户不需要在主脚本中加入成千上万行毫不相关的特定游戏逻辑。主脚本只需保持最纯净的 UI 框架和通用功能，而针对特定游戏或特定需求的功能，可以封装为独立插件，通过外部注入或热加载的方式运行。这打破了传统闭源脚本“只能官方更新”的局限，形成了一个可以自我进化的生态，同时也降低了主脚本的体积和内存占用。
