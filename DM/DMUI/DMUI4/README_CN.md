# DMUI4 API 框架

DMUI4 是一个为 Roblox 客户端执行器（Client-side Executor）设计的现代化、全功能 Lua UI 框架与脚本库。项目采用模块化设计，提供丰富的 UI 组件、全局状态管理、多语言支持以及多种游戏内实用功能。

## 核心特性

*   **动态右键菜单**：支持基于按钮绑定的自定义右键菜单，适配 PC 端与移动端，带有屏幕边缘自适应及多语言动态重绑。
*   **玩家档案系统**：支持输入 UserId 或用户名查询。可获取账户创建时间、年龄、好友、封禁状态、粉丝/关注数等。
*   **通知与历史系统**：支持多位置提示、超时自动关闭、按钮交互。内置独立的通知历史记录窗口，支持持久化保存与动态清理。
*   **游戏实用功能集成**：
    *   **统一飞行**：整合标准、载具、CFrame 三种飞行模式，支持速度调节。
    *   **观战系统**：自动跟随目标重生，防视角重置，退出时安全恢复本地视角。
    *   **实时定位**：基于 ViewportFrame 计算目标相对距离与方向。
    *   **对象/玩家选择器**：提供标准化的 UI 供脚本调用以选择游戏内的模型、部件或在线玩家。

# 插件开发优势

DMUI4 在核心主脚本中预留了 `PluginAPI` 接口。由于 Roblox 上不同游戏的服务器架构与玩法差异巨大，主脚本无法兼顾所有特定游戏逻辑。因此，DMUI4 采用“主框架+插件”的互补架构，针对特定服务器或定制化需求的功能，均可通过插件来实现。

在 DMUI4 生态内开发插件，具备以下显著优势：

### 1. 突破多游戏兼容性瓶颈
主脚本（DMUI4 核心）如果内置所有特定游戏的逻辑会导致代码极度臃肿，且易因单一游戏更新引发崩溃。通过编写独立插件，开发者可以针对特定游戏进行深度定制和快速迭代，完全不必等待主框架更新，也不会影响主框架的稳定性。

### 2. 极速开发与开箱即用
无需从零处理 UI 绘制、窗口拖拽、分辨率自适应等非核心问题。在 DMUI4 中开发插件可以直接调用现成的高级组件：
- 调用 `BuildWinUI` 生成统一风格、支持缩放和拖拽的模板窗口。
- 直接复用现成的通知系统、玩家选择器、右键菜单等交互组件。
让开发者将 100% 的精力投入到插件的核心业务逻辑上。

### 3. 统一的交互与视觉体验
所有 DMUI4 插件共享同一套底层 UI 规范：一致的窗口聚焦动画、智能适配 PC 与移动端的右键响应逻辑、统一的音效反馈与主题颜色。这保证了最终用户在面对任何第三方插件时，学习成本几乎为零。

### 4. 核心框架与业务逻辑解耦
通过 `APIFold` 提供统一的接口调用（如飞行、观战、定位等），插件无需关心底层物理飞行或防视角重置的具体实现。这种高内聚、低耦合的架构使得：
- 底层 API 的更新或 Bug 修复会瞬间惠及所有插件。
- 插件只需专注自身业务，即便插件内部出错，也不会轻易导致整个 DMUI 核心框架崩溃。
